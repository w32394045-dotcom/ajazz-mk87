## 一句话结论

v0.1.8.7 是一个「灯效不再走丢」的可靠性版本：修复 **开着音乐律动上传 GIF 必失败**，
并解决 **律动停止 / 程序崩溃 / 拔线 / 上传之后键盘变成「逐键灯效」** 的系统性问题。
原理是新增一份**持久化灯效账本**：每次灯效切换都记录，进帧流前先落盘「结束后要恢复成什么」，
崩溃/拔线/关软件后下次启动或重连自动补写；逐键态也能恢复。

## 1. 上传 GIF 为什么以前会失败

旧版在上传导出时，音乐律动的逐键帧流还在以每秒约 140 个包的速度写键盘的另一个接口，
TFT 上传需要键盘「整机独占」，于是上传的第 1 个包永远等不到确认，直接失败。
现在：**开始写设备前**自动暂停音乐律动（转换预览期间照常播放），上传结束自动按原参数恢复；
屏幕上也会显示「已自动暂停音乐律动，完成后自动恢复」。

## 2. 为什么以前一停律动就变逐键灯效

音乐律动必须把键盘切到「自定义帧」模式才能逐键亮；固件在**停止收帧约 5 秒后**会自动回落到
逐键自定义表。旧版恢复灯效时如果快照已被污染（mode 回读 0）或键盘恰好离线，就会「跳过恢复」，
键盘于是露在逐键态，而且下一次还会循环。新版用持久化账本 + 回读校验 + 兜底静态恒亮解决，
**逐键自定义本身也能写回**。

## 3. 崩溃 / 强杀 / 拔线

- 进入音乐律动前，程序会把「结束后要恢复成什么」原子写入配置文件（崩溃也不会丢）。
- 程序崩溃 / 被强杀：**重开程序后约 1~2 秒**自动补写灯效。
- 键盘拔插：重新连上后自动补写（若音乐自动续播，会直接回到帧流，不露逐键态）。
- 唯一空窗：程序被强杀且还没重开时，没有进程能替键盘写灯效，键盘会先显示逐键态——重开即修复。

## 4. 升级提醒

1. 安装 v0.1.8.7 前先**退出正在运行的旧版本**（避免旧实例占着 USB 句柄）。
2. 直接覆盖安装即可（Windows 安装版 / 便携版 / Linux deb、rpm），无需重装驱动。
3. 若新版本识别不到键盘：拔插一次键盘 USB 线，或重启程序。

## 5. 还有问题怎么反馈

- 应用内：**设置 → 日志与诊断 → 一键导出诊断包**；
- 日志位置：Windows `%LOCALAPPDATA%\mk87\logs`（`crash.log` 记录崩溃栈）；Linux
  `~/.local/state/mk87/logs`；
- 附上操作时间（精确到分）、连接方式（USB / 2.4G）与现象，便于对照日志时间线。
